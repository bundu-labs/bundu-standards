# Standards register

The external standards the platform builds on, by domain. This is the **one**
list of them. The canonical data model maps every field to one of these, so a
record means the same thing in MongoDB, PostgreSQL, Cassandra, JanusGraph, Doris,
on the event stream and in JSON-LD.

|                 |                                                                                                                                                                                                                                                                                                             |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Source**      | [`register.yaml`](register.yaml). The tables below and the seed are generated from it (`python3 register/tools/register.py write`); edit the YAML, never the tables.                                                                                                                                        |
| **Versions**    | "Current at source" was checked against each standard's official source on 2026-10-02; entries that name a later date were re-checked in the standards audit (`nyuchi/data-infra` `docs/standards-audit-2026-10.md`).                                                                                       |
| **Status**      | **Adopted** standards are in force. **Proposed** ones are listed, seeded inactive, and wait for the owner. Most adopted entries were already cited by the owner's documents or the live validators; the rest were adopted by the owner's decision of 2026-10-02 (cited `OD`).                               |
| **In the data** | MongoDB `integrations.standards` holds the register as records. [`seed/integrations.standards.json`](seed/integrations.standards.json) is one document per standard. How many documents the database holds is not written here: it is measured by `register.py live`, because a number in prose goes stale. |

## Gaps between what is adopted and what is current

These are places where a standard the platform has adopted has moved on, or is
cited loosely.

- **G-1. A2A version.** Fundi's agent card declares `protocolVersion` 0.3.0
  (`agent-tools/fundi/src/a2a/card.ts`). A2A 1.0.0 has been released.
- **G-2. AP2 mandate shape.** `bushtrade-mcp/src/ap2.ts` builds v0.1-style
  `Intent`, `Cart` and `Payment` mandates as W3C VCs. The official v0.2
  specification defines **Checkout** and **Payment** mandates, each Open or
  Closed, secured as SD-JWT credentials. Mandates are unsigned today
  (`proof: null`), so nothing in the wild needs migrating. Re-base on v0.2
  before any signing key is provisioned.
- **G-3. WCAG version.** The architecture says "WCAG AAA" with no version, and
  Mzizi's contrast functions cite WCAG 2.1. The commitment is **WCAG 2.2
  AAA**.
- **G-4. APCA is not normative.** No W3C standard requires APCA, and the WCAG 3
  Working Draft says its contrast algorithm "is yet to be determined". Keep
  APCA as a design target, but report conformance against WCAG 2.2.
- **G-5. what3words is proprietary.** It may be an extra identifier, never a
  place's only address. Always fill `plusCode` alongside it.
- **G-6. OAuth 2.1 is still a draft** (version 16, IESG milestone Dec 2026).
  Cite it as one until it is an RFC.

## Keeping the database in step

Nothing in this repository writes to MongoDB. Loading the seed is an owner step,
and checking that it was done is not:

```sh
# export integrations.standards from the cluster, read-only, then:
python3 register/tools/register.py live export.json
```

The command lists documents missing from the database, documents in the
database that the register does not know, and any field that differs. A clean
run prints "the database matches the register". Loading, when it reports drift:

```sh
mongoimport --db integrations --collection standards --jsonArray --mode upsert \
  --file register/seed/integrations.standards.json
```

The vocabulary terms live in this repository's README and `src/terms.rs`, not
here.
